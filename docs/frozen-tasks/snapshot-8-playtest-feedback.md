### A-1. 「WASD 无法移动」根因与修复（✅ Snapshot-9 落地 → 2026-09-29 实机通过）

实机现象（快照8）：进训练场后 WASD / 开火 / 鼠标视角全灭。

**根因链（两个互相放大的缺陷）**：

1. **轮盘 `held_key` 残留**（`HostCode/hud/hud_item_wheel.rs`）：原实现把"松开 3/4"的处理放在
   `if !state.open && blocked { return; }` **之后**。若在按住 3/4 期间被模态（F/M/暂停）打断，
   松开事件被吞 → `held_key` 永不复位 → `held` 持续累积 → 在**无按键**时 `state.open` 自发置真并**永久卡死**。
2. **二级面板无法 Esc 收起**（`HostCode/hud/hud_interact.rs`）：`interact_input` 里
   `if loot.open || wheel_state.open { return; }` 排在 Esc 处理**之前**，一旦轮盘（或面板）异常残留
   `open`，Esc 被让位吞掉 → `interact.panel_open` 无法清除 → `gameplay_input_active` 恒假。

**修复（Snapshot-9）**：

- `item_wheel_input` 重写为三段式：**① 松开优先结算**（不受任何门控影响，是本次会话的唯一出口）；
  **② 键已不再按住却仍在会话中**（窗口失焦等丢事件）→ **兜底复位**；**③ 其它模态接管 → 整体丢弃会话**。
- `interact_input` 把 **Esc 关闭二级面板提到轮盘/物资箱让位之前**，任何残留 `open` 都能被收起。

> 附带说明：报告称"二级面板在无输入下自行展开"。全仓穷举确认 `open_panel` **唯一**置位路径是
> `confirm_entry ← interact_input` 的 `F/Enter just_pressed`，故"自开"实为测试者按 F，
> 真正缺陷是随后**被轮盘残留卡死**（Esc 失效）。该路径已随上述修复关闭。
