# 计划 0002 · Bevy 0.16 强制破坏项迁移

> **状态：已批准 · 已执行完成（`cargo check` 退出码 0、0 error）** —— 本计划经 `plan-interrogation` 七问逐条确认后落地。
> **归属版本 `0.14.1`（`z` 细节，**不升版本号**）** —— 0.14.1 条目原已声明「Bevy 0.16（迁移未实施）」，
> 本次实施即补全该版本，使其成为「完全体」；不触碰线格式 → **不触发 `y+1`**。
> **归属**：客户端表现层 `HostCode/`（纯编译面）；不动契约层 / 服务端 / 线格式。
> **前置依据**：`docs/barek-history.md` 的 `0.14.1` 条目（② Bevy 0.16 声明（声明态））；
> 官方迁移指南 <https://bevy.org/learn/migration-guides/0-15-to-0-16/>。

---

## 零、一句话定义

把 `HostCode` 从 Bevy 0.15 基线迁到 0.16，**只迁编译不过的强制破坏项**，以 `cargo check` 报错为**唯一权威清单**；
0.16 中「已弃用但仍可编译」的 API 一律不动（沿用 0.12.1 / 0.12.4 的「小步升级」纪律）。

---

## 一、迁移边界（已定决策）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 编译工具 | 本机无 `cargo-wrap` → **裸 `cargo` 过渡**，条目明示该偏离 |
| 2 | `despawn_descendants` 目标写法 | **`despawn_related::<Children>()`** |
| 3 | 版本号 | 补全 `0.14.1`，**不升版**；三端 `Cargo.toml` 版本号不动 |
| 4 | 文档同步 | 本轮只改 BarekHistory + `HostCode/Cargo.toml`；README / module-boundaries / ADR 0008 留发布时统一 |
| 5 | 计划文档 | 本文件 |
| 6 | 验证深度 | **仅** `cargo check --workspace --all-targets`；release build 归发布闸门 |
| 7 | 执行顺序 | 先升依赖 → check-first 拿清单 → 按报错迭代 |

**明确不做**：不迁 `get_single*`（52 处 / 15 文件，可编译）；不跑 `--release`；不改版本号 / 不打 tag / 不发 Release；不碰契约 YAML 与服务端。

## 二、全量清单

### 2.1 已确证（grep + 官方指南交叉核对）

| 项 | 落点 | 数量 | 范式 |
|---|---|---|---|
| `ChildBuilder` → `ChildSpawnerCommands` | 18 文件（含 helper 签名 `parent: &mut ChildBuilder`） | 24 | 类型名机械替换 + import 同步 |
| `despawn_recursive()` → `despawn()` | `net/snapshot.rs` ×2、`menu/pause.rs` ×3 | 5 | 0.16 起 `despawn()` 已递归 |
| `despawn_descendants()` → `despawn_related::<Children>()` | `hud/minimap.rs`、`hud/interact/panel.rs` | 2 | 掏空容器再重建，语义不变 |

> **实测修正**：`despawn_recursive` 在 0.16 中**已弃用但仍可编译**（仅告警，非强制项）—— 按本计划顺手迁移以消除告警。
> 因此编译层面真正的强制项只有 `ChildBuilder` / `despawn_descendants` / `AmbientLight`（见 2.2）三处。

### 2.2 编译暴露（未知强制项 · 已捕获）

0.16 破坏点众多，grep 只能覆盖已知类别；实跑 `cargo check` 后，除 2.1 外**新增捕获 1 项**：

| 项 | 落点 | 数量 | 范式 |
|---|---|---|---|
| `AmbientLight` 新增字段 `affects_lightmapped_meshes` | `world/scene.rs` | 1 | 补默认 `true`（本世界无光照贴图网格，保持既有全局环境光语义） |

未再暴露其他编译错误。

### 2.3 明确不迁（弃用但可编译）

- `get_single*` / `get_single_mut*` → `single*`（返回 `Result`）：52 处 / 15 文件，仅产生弃用告警，**不动**。

### 2.4 本仓未使用（不受影响）

`.single()`、`Parent` / `ChildOf`、`weak_from_u128`、`set_volume`、`a11y::Focus` —— 均无代码引用。

## 三、改造范式

1. **类型改名**：`use bevy::prelude::*` 下统一替换 `ChildBuilder` → `ChildSpawnerCommands`（含函数签名形参）。
2. **递归删除**：`commands.entity(e).despawn_recursive();` → `commands.entity(e).despawn();`。
3. **掏空子级**：`commands.entity(e).despawn_descendants();` → `commands.entity(e).despawn_related::<Children>();`。
4. **doc 注释同步**：`minimap.rs` 中写死的 `DespawnRecursiveExt::despawn_descendants` 一并更新，避免注释与 API 不符。

---

## 四、执行顺序

1. `HostCode/Cargo.toml`：`bevy = "0.15"` → `"0.16"`，注释「0.16 声明态·本轮未实施」→「已实施」；
2. 跑 `cargo check --workspace --all-targets`（首跑拉取并编译 0.16 依赖，最重；此后增量快）；
3. 按报错修复：2.1 确证项 + 2.2 未知项；
4. 再 check 至**退出码 0、无 error**（弃用告警不计）。
