# 0007 · 射击表现与命中反馈（激光瞄准 / 曳光 / 准星左侧伤害反馈）

> **来源**：owner 提出的两个需求——①枪械射击特性（射击激光瞄准、子弹痕迹）；②准星左侧射击反馈。
> **性质**：已过 plan-interrogation 全拷问、owner 逐项确认的**实施计划**；本文档即动工依据，
> 动工时不再重新盘方案。当前状态：**已批准、未动工**（2026-10-07）。
> **关联**：[README〈不稳定警告〉](../../README.md)（动工时新建）、[protocol.yaml](../contracts/protocol.yaml)、[BarekHistory](../barek-history.md)

## 一、已定决策（拷问结论，逐条经 owner 确认）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 曳光/激光**仅本人可见**；远程玩家曳光留待下版本（不做 `Shot` 事件广播） | 远程曳光需 L2 协议新增广播事件，成本翻数倍；本人可见纯客户端+一次事件扩字段即可拿到 90% 手感收益 |
| D2 | `EventKind::Hit` 扩字段：`damage: f32` + `reaction: Option<String>` | 伤害数值/反应由服务端权威结算，客户端无权推算；须随事件下发。**L2 不兼容变更 → `y+1`（0.14.x → 0.15.0）+ `WIRE_VERSION` 14→15 + 迁移指南** |
| D3 | 激光线做**体素遮挡截断**：客户端 DDA 射线 marching（与手雷预览同思路），止于命中目标表面 | 固定长线穿墙一眼假；客户端已有体素布局数据，每帧一次成本可忽略 |
| D4 | 命中反馈：准星左侧**单条飘字**，0.8s 淡出，新命中覆盖旧条目；有反应时两行（伤害 + 反应名）；爆头伤害数字变黄 | 一次命中的复合展示而非历史列表；覆盖语义在连发下体验最好；`is_headshot` 服务端已带，变色零成本 |
| D5 | 文档：README 新开**「不稳定警告」独立章节**，**迁移现有所有警告**到此（〈八〉渲染内存保修边界、附录 dead_code 告警说明），并新增「曳光仅本人可见」警告；`shooter.rs` 模块头补协议留待点说明 | owner 指定：警告集中一处，不散落 |

### 明确不做什么（最容易跳过，最关键）

- ❌ 远程玩家曳光 / `Shot` 事件广播（下版本）
- ❌ 枪口火花、弹孔、弹壳
- ❌ 堆叠伤害数字列表 / 飘字飞行动画
- ❌ 激光样式设置 UI（只留模块头常量）
- ❌ 不新增 docs/module/ 模块文档（纯 launcher 表现域新文件，不触碰既有模块边界）

## 二、全量清单（按操作顺序分批）

### 批次 A · 契约层（`ContractCode`）

1. `net/protocol.rs`：`EventKind::Hit { source_id, target_id, is_headshot }` → 增加 `damage: f32`、`reaction: Option<String>`（反应名用 `String` 保持线格式 JSON 简单；服务端序列化时填反应枚举名）。
2. `net/packet.rs`：`WIRE_VERSION` 14 → 15。
3. `net/codec.rs`：编码分支同步 + 往返测试补新字段断言。

### 批次 B · 服务端（`ServerCode`）

1. `damage/resolver.rs`：`resolve` 目前无返回值、反应在内部消化——改为**返回反应结果**（服务端内部签名，不动线格式归属）。
2. `combat/shooter.rs`：结算后构造 `CombatEvent::Hit` 时携带真实伤害与反应结果；模块头补注释「客户端曳光仅本人本地可见；跨玩家曳光需协议新增 `Shot` 事件，当前未实现」。
3. `net/stages.rs`：事件转投处适配（若签名变）。
4. `combat/tests.rs`：事件载荷断言补 damage/reaction。

### 批次 C · 客户端表现层（`HostCode`）

1. **新文件** `world/aim_line.rs`：激光瞄准线 + 曳光弹。
   - 瞄准线：相机视线 → DDA 体素步进求地形交点 → 与目标实体（快照位置）求球面交点，取**近者**截断；
   - 曳光：开火瞬间从枪口收敛到命中点的短暂线段（README 已承诺「曳光从枪口收敛到命中点」）；
   - 细红色线 + 低透明度，参数集中模块头常量（不进设置 UI）。
2. **新文件** `hud/hit_feedback.rs`：准星左侧伤害/反应飘字。
   - 资源 + 系统：单 Text 实体 + 计时淡出（0.8s），新命中覆盖；
   - 有反应时两行（伤害行 + 反应名行）；爆头黄字、普通白字。
3. `flow/state.rs`：消费 `EventKind::Hit` 新字段，写入反馈资源（当前 `Hit` 分支被 `_ => {}` 吞掉）。
4. `launcher/mod.rs`：注册新资源与系统（遵守 ADR 0004：launcher 只装配，不定义资源）。

### 批次 D · 文档与版本

1. README：新开**〈不稳定警告〉**章节，迁移全部既有警告 + 新增「曳光仅本人可见」；越肩瞄准段落原警告处留指针。
2. `docs/contracts/protocol.yaml`：`EventKind.Hit` 同步新字段。
3. `docs/barek-history.md`：新版本条目（含迁移指南）。
4. 三端 `Cargo.toml` + `Cargo.lock`：0.14.3 → **动工时按上文「版本号判断」现场判定**（`y+1`，按 `[[package]] name` 精准编辑，`cargo metadata` 零编译验证自洽）。
5. `ServerCode/net/web/portal.html`：绑定包版本随动。

### 版本号判断

- 本特性为**协议不兼容变更**（`y+1`：`EventKind::Hit` 加字段；`WIRE_VERSION` 15；双端必须同步升级，无渐进兼容路径），原判 `0.15.0`。
- **冲突修正**：README〈六〉第 5 条（区域光照着色器套件，计划 0001）已占用 `0.15.0` 目标号。两条均为 `y+1` 不能同号——**本特性动工时按「届时最新已发布版本 +1」现场判定**：若 0001 已以 `0.15.0` 发布则本特性取 `0.16.0`；若本特性先动工则取 `0.15.0`，0001 顺延。批次清单与验证命令不受影响。
- 预发布标记（`--prerelease`），发布走 compliant-delivery 五件套。
