# 计划 0001 · 三角形区域光线追踪着色器套件

> **状态：已采纳 · 计划中（未实现）** —— 本文只描述设计，**不含任何可运行代码**。
> **目标版本 `0.15.0`（`y+1`，协议不兼容）** —— 落地时 `WIRE_VERSION` 由 `14` 升到 `15`。
> **归属**：客户端表现层新增顶层模块 `HostCode/shader/`；服务端新增子域 `ServerCode/scene/`；契约层 `ContractCode` 新增线格式类型。
> **范式去向**：README〈六、已采纳未来形态〉第 5 条。

---

## 零、一句话定义

以**三角形区域**（而非逐像素）为光照计算单位，在不使用 DXR / Vulkan Ray Tracing / RT Core / 任何专用光追单元的前提下，
用一大块 **1m³ 单元网格**作加速结构、以**少量共享光线**产出像素风格的**区域阴影 / 区域 AO / 低精度反射 / 简单间接光**，
结果写入**像素块**并整体放大到 1080p / 2K。

风格限定：**只适用于像素风 / 低模 / 体素 / 方块化场景**。写实几何不在适用范围内。

## 一、设计约束与取舍

| 约束 | 取值 | 说明 |
|---|---|---|
| 画面风格 | 像素风 / 低模 / 体素 / 方块化 | 平滑曲面、高频法线贴图场景不适用 |
| 计算单位 | **三角形区域** | 一次性算出区域共享光照，不再逐像素求交 |
| 空间密度 | 每 1m³ 单元 **≤ 1000 三角形** | 超限触发减面 / 合并 / 实例化 / LOD（见模块 M1） |
| 算力预算 | 1080p/2K 像素风下 **几十 GFLOPS 量级** | compute 逐块，块数 = 屏宽/块径 × 屏高/块径 |
| 硬件依赖 | **无** DXR / VK RT / RT Core | 纯 compute shader，任意支持 WGSL 的 GPU |
| 输出分辨率 | 低分辨率像素块 → 放大到 1080p / 2K | nearest 放大，保像素锐利 |
| 代码规模 | 核心几千行 | 单文件守 600 行红线，模块单职责 |
| 反射层数 | **最多 1–2 层** | 不做递归多 bounce |
| 降噪 | **不使用**复杂降噪器 | 靠区域共享 + 像素块自带的"天然模糊" |

**阶段性取舍（见 [ADR 0008](../adr/0008-triangle-region-radiance.md)）**

1. **后端收敛为 WGSL 单源**：原范式的「SPIR-V 1.0 + Vulkan/GL/DX11/DX12/Metal 五后端」改为 **WGSL 单一着色器源 + Bevy/wgpu**。
   wgpu 已原生覆盖 **Vulkan 1.x / OpenGL(ES) / DX12 / Metal**，无需手写后端。
2. **DX11 显式剔除**：wgpu 不支持 DX11，本项目亦不再维护该路径 —— 列为**范式不支持项**，非缺陷。
3. **几何由服务端权威下发**：SceneGrid 的加速结构由服务端构建，客户端按需拉取（见第四节）。

## 二、整体架构

### 2.1 三端职责

```
┌─ 服务端 ServerCode（零 bevy）────────────────────────────────────┐
│  scene/  ：把契约静态布局 MapLayout 展平成「每 1m³ 单元三角面汤」  │
│            · unit.rs  单元切分 + 密度约束（M1 服务端侧）          │
│            · index.rs 构建 + 按坐标查询                            │
│  net/stages.rs ：只做编排——收请求 → 问 scene → 回响应            │
└───────────────────────────┬──────────────────────────────────────┘
                            │ 线格式：ClientMessage::RequestSceneUnits
                            │         ServerMessage::SceneUnits
┌─ 契约层 ContractCode（零 bevy、零逻辑）──────────────────────────┐
│  scene.rs ：UnitCoord / TriangleData / WireUnit（只传面汤）       │
│  net/protocol.rs ：成对消息                                        │
│  port.rs ：pub trait SceneSource（来源可 mock）                    │
└───────────────────────────┬──────────────────────────────────────┘
                            │
┌─ 表现层 HostCode（Bevy 0.15 / wgpu）──────────────────────────────┐
│  shader/ ：区域光照着色器套件（本计划的主体）                      │
│    · grid.rs    重建 SceneGrid + 密度告警（M1 客户端侧）          │
│    · region.rs  三角形区域划分 + PixelBlock（M2）                 │
│    · trace.rs   区域光线发射 + 1m³ 步进求交（M3 + M4）            │
│    · shade.rs   五路光照通道（M5）                                │
│    · raster.rs  像素块着色写回（M6）                              │
│    · backend.rs WGSL 单源 + Bevy/wgpu 渲染图接线（M7）            │
│    · debug.rs   可视化调试                                        │
│  flow / net ：拉取资源与请求上报（复刻 WorldCatalog 范式）        │
└───────────────────────────────────────────────────────────────────┘
```

### 2.2 七模块 → 文件映射（**模块边界即文件边界，杜绝单片**）

| # | 模块 | 服务端文件 | 客户端文件 | 着色器文件 |
|---|---|---|---|---|
| M1 | 场景密度约束 | `scene/unit.rs` | `shader/grid.rs` | `grid.wgsl` |
| M2 | 三角形区域划分 | — | `shader/region.rs` | `region.wgsl` |
| M3 | 区域光线发射 | — | `shader/trace.rs` | `trace.wgsl` |
| M4 | 空间步进与求交 | — | `shader/trace.rs` | `trace.wgsl` |
| M5 | 光照计算 | — | `shader/shade.rs` | `shade.wgsl` |
| M6 | 像素块着色 | — | `shader/raster.rs` | `raster.wgsl` |
| M7 | 多后端抽象（**重定义**） | — | `shader/backend.rs` | — |
| — | 共享结构 / 常量 | — | `shader/mod.rs` | `common.wgsl` |

> **M3 与 M4 同置 `trace.rs` / `trace.wgsl`** 的理由：求交步进与光线发射共享同一套 `Ray` / `Hit` 与单元遍历内核，
> 拆成两个文件会强行切开一段连续性极强、复用率极高的热路径；二者仍以**独立函数**分界（发射函数只决定"打哪几条"，求交函数只决定"打到什么"）。

### 2.3 依赖方向（DAG，无环）

```
HostCode/shader  →  HostCode/flow（资源：SceneUnits）  →  ContractCode
HostCode/shader  →  ContractCode（线格式 + Port）
ServerCode/scene →  ContractCode（MapLayout）
ServerCode/net/stages → ServerCode/scene（经 SceneSource 实现，不直调内部类型）
```

**红线自检**
- 客户端 `shader` **不得** `use` `ServerCode` 任何类型（判据：`HostCode/Cargo.toml` 无 `cute_of_duty_server`）。
- `shader` 不直连 `net`：新增单元的请求经 `flow` 的资源 + 事件，`net` 适配器消费（复刻 `WorldCatalog` 范式）。
- 每个新文件预期 **< 600 行**；单文件超限即按上表继续细分，**不得**合并。

## 三、核心数据结构

### 3.1 线格式（`ContractCode/scene.rs`，零 bevy）

只传**面汤**，索引结构由客户端重建——避免冗余下发。

```rust
/// 1m³ 空间单元的三维整数索引。
/// 设计动机（Why）：以整数坐标而非世界浮点坐标作键，规避浮点哈希不稳定导致的单元漏查。
#[derive(Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct UnitCoord { pub x: i32, pub y: i32, pub z: i32 }

/// 线格式三角形：顶点 + 法线 + 材质编号（不含 id / 单元坐标，由客户端重建时分配）。
#[derive(Clone, Serialize, Deserialize)]
pub struct TriangleData {
    pub vertices: [[f32; 3]; 3],
    pub normal: [f32; 3],
    pub material_id: u32,
}

/// 一个单元的三角面汤 + 冗余自检字段。
/// 设计动机（Why）：`density` / `bounds` 与服务端切割结果冗余下发，客户端据此比对重建结果，
/// 一旦不一致即告警（把"两端切割不一致"这类静默错误显式暴露）。
#[derive(Clone, Serialize, Deserialize)]
pub struct WireUnit {
    pub coord: UnitCoord,
    pub triangles: Vec<TriangleData>,
    pub density: u32,
    pub bounds: [f32; 6], // [min.x,min.y,min.z, max.x,max.y,max.z]
}
```

### 3.2 客户端运行期（`HostCode/shader/`）

```rust
/// 1m³ 单元网格：全部光照求交的唯一加速结构（不建完整 BVH）。
pub struct SceneGrid {
    pub unit_size: f32,                      // 恒为 1.0
    pub units: HashMap<UnitCoord, UnitData>, // 已拉取到的单元
}

pub struct UnitData {
    pub triangle_ids: Vec<u32>, // 指向 TriTable 的索引
    pub density: u32,           // 三角形数，> 1000 触发 M1 约束
    pub bounds: Aabb,
}

pub struct Triangle {
    pub id: u32,
    pub vertices: [Vec3; 3],
    pub normal: Vec3,
    pub material_id: u32,
    pub unit_coord: UnitCoord,
}

/// 一个屏幕像素块：区域光照的最终承载体。
pub struct PixelBlock {
    pub screen_rect: [u32; 4], // x, y, w, h（块径 4/8/16 可配）
    pub center: Vec2,
    pub triangle_ids: Vec<u32>, // 覆盖该块的三角形（按深度排序）
    pub lighting: LightingResult,
}

/// 五路光照的合成结果；每路可独立开关（关掉即不计算、不占预算）。
pub struct LightingResult {
    pub diffuse: Vec3,
    pub specular: Vec3,
    pub shadow: f32,
    pub ao: f32,
    pub reflection: Vec3,
    pub indirect: Vec3,
}
```

> **所有权唯一**：`SceneGrid` 由 `shader::grid` 独占持有；`region` / `trace` / `shade` / `raster` 只吃**不可变借用**，不持 `&mut`。

### 3.3 数据规模自检（默认档）

| 分辨率 | 像素块 8×8 时块数 | 每块光线上限 | 每帧光线上限 |
|---|---|---|---|
| 1080p (1920×1080) | 240×135 ≈ **32,400** | 5 | ≈ **162,000** |
| 2K (2560×1440) | 320×180 ≈ **57,600** | 5 | ≈ **288,000** |

关掉反射 / 间接后光线条数近半，是该套件的**主要性能旋钮**。

## 四、下发协议（Q4 = 客户端按需拉取）

### 4.1 成对消息（`ContractCode/net/protocol.rs`）

```rust
// 上行
ClientMessage::RequestSceneUnits { coords: Vec<UnitCoord> }

// 下行
ServerMessage::SceneUnits { units: Vec<WireUnit> }
```

### 4.2 拉取时序

1. 客户端重建 SceneGrid 时发现某 `UnitCoord` 缺失 → 记入**待拉取集**并去重。
2. `shader` 经 `flow` 发出请求（**每帧合并**一次，绝不逐块发包）。
3. `net` 适配器编码上行 → 服务端 `net/stages.rs` 编排 → `scene::index` 查询 → 回 `SceneUnits`。
4. 客户端 `net` 解码写入 `flow` 资源 → `shader` 下一帧重建该单元并标记就绪。
5. **未就绪的单元按"空单元"处理**（不命中、不遮挡），呈现"逐步填充"；不做阻塞等待。

> **带宽护栏**：单次请求 `coords` 上限（如 64 个）与单响应单元上限（如 128 个）均在契约中定死；
> 超限则拆批，避免一条消息撑爆资源通道。

### 4.3 协议影响（落地时）

| 项 | 变更 |
|---|---|
| `WIRE_VERSION` | `14 → 15` |
| `docs/contracts/protocol.yaml` | 新增两条消息 + `version: 0.15.0` |
| `docs/barek-history.md` | 追加 `0.15.0` 条目（Breaking + 迁移指南） |
| `ServerCode/net/module.md` | 触碰 `net` 必须同 PR 补 |
| 版本号 | `x.y.z` 的 **`y+1`** → `0.15.0` |

**迁移指南要点**：新增上行 / 下行变体属**不兼容**变更，老端无法反序列化新变体；
双端必须**同时**升到 `0.15.0`，无渐进兼容路径。

## 五、着色器接口（WGSL）

### 5.1 统一接口（概念层；WGSL 无 `out` 参数，一律改为**返回值**）

```wgsl
// ── 输入（绑定组 0） ──────────────────────────────
@group(0) @binding(0) var<storage, read> scene_units  : array<UnitData>;   // SceneGrid 扁平化
@group(0) @binding(1) var<storage, read> tri_table    : array<Triangle>;
@group(0) @binding(2) var<storage, read> blocks       : array<PixelBlock>;
@group(0) @binding(3) var<uniform>       camera       : Camera;
@group(0) @binding(4) var<storage, read> lights       : array<Light>;
@group(0) @binding(5) var albedo_map   : texture_2d<f32>;
@group(0) @binding(6) var normal_map   : texture_2d<f32>;

// ── 输出 ─────────────────────────────────────────
@group(0) @binding(7) var blocks_out : storage, read_write  : array<LightingResult>;
@group(0) @binding(8) var<storage, read_write> stats : Stats;  // 默认不写

// ── 核心函数（与范式一一对应） ───────────────────
fn compute_pixel_block(tri: Triangle) -> PixelBlock;            // M2
fn shade_region(block: PixelBlock, tri: Triangle) -> LightingResult; // M5
fn trace_region_ray(ray: Ray) -> Hit;                           // M3/M4
fn compute_shadow(block: PixelBlock, light: Light) -> vec3;     // M5
fn compute_ao(block: PixelBlock) -> f32;                        // M5
fn compute_reflection(block: PixelBlock) -> vec3;               // M5
fn compute_indirect(block: PixelBlock) -> vec3;                 // M5
```

### 5.2 文件切分与 entry point（防单片）

| 文件 | entry point | 职责 |
|---|---|---|
| `common.wgsl` | — | 结构体 / 常量 / 工具函数（**无 entry**） |
| `grid.wgsl` | — | 单元遍历内核 |
| `region.wgsl` | — | 区域划分内核 |
| `trace.wgsl` | — | `Ray`/`Hit` + 步进求交 |
| `shade.wgsl` | — | 五路光照通道 |
| `raster.wgsl` | `@compute fn main_blocks` | **唯一入口**：逐像素块 → 写 `blocks_out` |
| `upscale.wgsl` | `@vertex` / `@fragment` | 极薄放大 pass（**无光照逻辑**） |

**组合方式**：naga_oil `#import`（Bevy 0.15 内置）拼装，**一模块一职责**，禁止把所有函数塞进单个 `.wgsl`。

### 5.3 管线形态（compute 主导）

1. **Compute pass**：`main_blocks` 按 `blocks` 数组分发（workgroup 64），逐块执行
   区域划分 → 发射 ≤5 条光线 → 步进求交 → 五路光照 → 写 `blocks_out`。
2. **放大 pass**：把 `blocks_out` 上传为一张低分辨率纹理，nearest 采样铺满 1080p/2K —— **不含任何光照计算**。
3. **关闭的通道**：在 WGSL 侧以 `const` 开关（`#ifdef` 等价物）编译期裁剪，而非运行期 `if` 分支。

## 六、各模块实现

> 以下每节按"操作细节"逐段展开：**输入 → 处理 → 输出 → 边界**。

### M1 · 场景密度约束（服务端 `scene/unit.rs` + 客户端 `shader/grid.rs`）

- **输入**：契约静态布局 `MapLayout`（服务端）；`WireUnit` 列表（客户端）。
- **处理**：
  1. 按 `unit_size = 1.0` 把几何 AABB 映射到单元整数坐标；
  2. 每个单元收集落入其中的三角形索引，累加 `density`；
  3. `density > 1000` → 触发**约束策略**（优先级递减）：合并共面三角形 → 减面 → 同型 prop 实例化 → 降一级 LOD；
  4. 客户端重建时用服务端下发的 `density` / `bounds` 做**一致性自检**，不符即告警。
- **输出**：`SceneGrid`（客户端）/ `Vec<WireUnit>`（服务端）。
- **边界**：本模块**只做切分与约束**，不发射光线、不接触相机。

### M2 · 三角形区域划分（客户端 `shader/region.rs`）

- **输入**：一个 `Triangle` + 相机参数 + 块径配置。
- **处理**：
  1. 把三角形投影到屏幕，求其包围盒；
  2. 按块径（默认 **8×8**）量化出覆盖的 `PixelBlock` 集合；
  3. 每个块记录 `screen_rect`、`center`、以及覆盖它的 `triangle_ids`（按深度排序）。
- **输出**：`PixelBlock` 列表（去重后即 compute 的分发基数）。
- **边界**：本模块**不判可见性、不求交**，只负责"哪块归哪个三角形"。

### M3 · 区域光线发射（客户端 `shader/trace.rs` 上半）

- **输入**：`PixelBlock` + 光照开关位。
- **处理**：从**块中心**（或三角形重心）以**少量代表性采样**发射：
  - 主光方向 1 条（决定基础明暗朝向）；
  - 阴影 1 条（朝最近光源）；
  - AO 1 条（半球法向抖动）；
  - 反射 1 条（镜面方向，**最多再跟 1 层**）；
  - 间接 1 条（余量方向）。
  同一块的这 5 条光线**只服务该块**，结果被块内所有像素共享。
- **输出**：`Ray[]`（≤5）。
- **边界**：本模块**只决定"打哪几条"**，求交全部委托 M4。

### M4 · 空间步进与求交（客户端 `shader/trace.rs` 下半）

- **输入**：`Ray` + `SceneGrid`。
- **处理**：
  1. 以 **1m³ 单元网格**做 DDA 步进（Amanatides–Woo）；
  2. 每步入一个单元，**只检测该单元内 `triangle_ids`**，命中即返回；
  3. 单元为空 / 越界 / 超出最大步数 → 未命中。
  - **不构建完整 BVH**：单元即粗加速结构，三角形数 ≤1000 保证单单元线性扫描可接受。
- **输出**：`Hit { hit: bool, t: f32, point: vec3, normal: vec3, material_id: u32 }`。
- **边界**：本模块不关心光照语义，纯几何。

### M5 · 光照计算（客户端 `shader/shade.rs`）

五路通道，**各自一个纯函数、各自可开关**：

| 通道 | 函数 | 做法 | 典型光线数 |
|---|---|---|---|
| 基础漫反射 + 高光 | `shade_region` 内联 | Lambert + Blinn-Phong（低模不需 PBR） | 0（解析） |
| 区域阴影 | `compute_shadow` | 朝光源 1 条硬光线，**块内共享** → 边缘天然呈块阶梯 | 1 |
| 区域 AO | `compute_ao` | 半球 1 条抖动光线，命中距离映射到 `[0,1]` | 1 |
| 低精度反射 | `compute_reflection` | 镜面 1 条，命中后取该点材质色，**最多再反射 1 层** | 1 |
| 简单间接光 | `compute_indirect` | 余量方向 1 条，命中即回灌漫反射色（单次溢出，不递归） | 1 |

- **输出**：`LightingResult`（六字段）。
- **边界**：本模块**只算数值**，不写纹理、不管像素块布局。

### M6 · 像素块着色（客户端 `shader/raster.rs`）

- **输入**：`PixelBlock` + `LightingResult`。
- **处理**：把区域光照结果**整体写入** `blocks_out[block_id]`；
  **不再逐像素重新求交**（这是本套件省算力的核心）。
- **输出**：低分辨率块缓冲区。
- **边界**：本模块不做采样放大（那是 `upscale.wgsl` 的事），不碰几何。

### M7 · 多后端抽象（**重定义**：客户端 `shader/backend.rs`）

原范式的"SPIR-V 1.0 + 五后端"在 WGSL 单源下落位为：

- **着色器源**：仅 WGSL（`common/grid/trace/shade/raster/upscale`）。
- **后端覆盖**：由 **wgpu** 提供 —— Vulkan 1.x / OpenGL(ES) / DX12 / Metal **免费获得**。
- **能力探测**：启动时读 wgpu `AdapterInfo`，记录实际后端，并在**不支持项**（DX11）时给出明确降级说明。
- **可迁移路径（可选，不在本计划范围）**：如需 SPIR-V / MSL / HLSL，可用 **naga** 从 WGSL 转译，而非手写五后端。
- **边界**：本模块是**唯一**接触 wgpu / Bevy 渲染图的地方；`grid/region/trace/shade/raster` 全部**与后端无关**。

## 七、性能与统计口径（默认档）

| 项 | 默认值 | 可调 |
|---|---|---|
| 像素块 | **8×8** | 4×4 / 16×16 |
| 每区域光线上限 | **5** | 关通道即减 |
| 反射层数 | **1**（最多 2） | 硬上限 |
| 统计采集 | **默认关闭** | 调试模式 ~1Hz 采样读回 |

**统计四项的采集方式**（贴合"不费性能的测试方法"）：

- `像素块数量`、`光线数量`：**CPU 侧直接算**（块列表长度 × 每块线数），零 GPU 开销。
- `单元命中次数`：GPU `atomic` 计数写 storage buffer，**仅调试模式**读回。
- `GPU 时间`：timestamp query，**仅调试模式**读回。

## 八、验证方式（实现阶段执行，本轮不跑）

1. **构造方块化测试场景**：每 1m³ 单元三角形数 ≤ 1000（超限场景另测 M1 约束是否触发）。
2. **区域阴影**：启用后验证阴影边缘随像素块**稳定**显示（无闪烁、无逐像素锯齿）。
3. **区域 AO**：验证墙角与接触阴影出现，且随块径变化呈预期的块化。
4. **低精度反射**：镜面物体能反射出周围**块状**场景（不要求清晰，要求稳定）。
5. **统计采集**：读出每帧光线数量、单元命中次数、像素块数量、GPU 时间。
6. **低配设备**：1080p 像素风画面稳定运行（掉帧则降块径 / 关通道）。

```
tools/cargo-wrap/target/release/cargo-wrap.exe check --workspace
tools/cargo-wrap/target/release/cargo-wrap.exe test  -p cute_of_duty_server
tools/cargo-wrap/target/release/cargo-wrap.exe build --workspace --release
```

## 九、明确不做（范围外）

- 不做逐像素光线追踪，不做递归多 bounce，不引入降噪器。
- 不手写 SPIR-V / GLSL / HLSL / MSL 后端，**不实现 DX11**。
- 不把 `shader` 做成通用渲染工具（它只服务像素风区域光照）。
- 不在本计划内改动任何 `.rs` 代码、线格式或版本号（本轮只出文档）。
