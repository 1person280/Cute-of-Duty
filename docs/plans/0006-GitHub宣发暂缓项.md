## D1. 完整浏览器 3D 客户端（WASM / Pages 试玩）

- **现状**：0.12.3 的 Web 桥只做到「能连上、握手、收快照」的极简 JS 骨架，体素渲染 / 输入 / 资源池全无。
- **卡点**：客户端依赖 `bevy_dylib` 动态装载 + 独立服务端进程 TCP；浏览器既无 dylib 也无原生 TCP。
- **重启条件**：
  1. 主线渲染内存问题（README〈八〉挂账）已有长期复验结论；
  2. 网络层确定浏览器侧替代方案（WS 桥已有，需评估快照解码在 wasm-bindgen 下的开销）;
  3. Bevy 0.16 的 wasm32 构建在「无 dylib」形态下验证可行（feature 门控 `bevy_dylib`）。
- **动工形态**：独立版本工程（预计 `y+1`），先出「训练场单机 WASM 包」最小闭环，再谈 Pages 嵌入。

## D2. 内嵌网页试玩（GitHub Pages）

- **现状**：不可行——依赖 D1 的浏览器 3D 客户端。
- **卡点**：无渲染就没有试玩，Pages 只能挂门面。
- **重启条件**：D1 最小闭环达成后，加一个 `pages-deploy` workflow（构建 wasm 产物 + 静态页 + Pages 发布）。
- **备注**：D1 未达成前，**GitHub 内的「试玩」入口由 Release zip + `启动游戏.bat` 承担**（已落地）。

## D3. Steam 商店页

- **现状**：超出「仅 GitHub」范围，且与「非商业同人」定位存在张力。
- **卡点**：①美术资产 CC BY-NC-SA（禁商用）与 Steam 发行需要重新划界（自建资产 vs 需替换的第三方素材）；②名称与题材的「致敬」边界在商业平台上需重新评估法律风险；③$100 Steam Direct 费用与收款主体。
- **重启条件**：上述三点的书面结论（定位 / 资产 / 合规），缺一不动。
- **备注**：即便不上 Steam，愿望单等价物是 GitHub Watch + Release 订阅——阶段 C 的基建已为此服务。
