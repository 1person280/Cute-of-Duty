## 角色建模规范——[YSM] 是，史蒂夫模型 (Yes Steve Model) 美学（钦定标准）

参考 mod：[YSM] 是，史蒂夫模型 (Yes Steve Model)，资料页
https://www.mcmod.cn/class/8616.html 。
视觉基准：同目录 **steve-model-mod-reference.webp**（YSM 的 Alt+Y 模型浏览器截图：
左侧 3D 预览 + 右侧模型网格与搜索，模型全是方块拼装的二次元角色——兔耳、双马尾、
外套、武器都是特征方块，且带待机动画）。
学的是**这个 mod 的模型美学**，不是原版裸史蒂夫；区别就在特征件、皮肤细节、比例、动画。

- **骨架**：沿用原版 Steve 方块骨架——头 8×8×8 / 身 8×12×4 / 臂腿各 4×12×4，
  总高 32 单位 ≈ 现有角色身高 1.8m（1 单位 ≈ 0.056m），保证与 demo3d 现有 voxel 角色共存。
- **特征方块**：骨架外追加兽耳（焦狸狐耳、雷豹豹耳、毒蜨虫翼…）、尾巴、发型块、
  帽子/护具层、手持武器——角色辨识度主要靠这些部件，参考图里 amiya 的兔耳、
  各角色的双马尾/大衣/武器都是加块，不是改骨架。
- **皮肤级细节**：脸画在头部正面（眼用 EYE_BLUE 友方 / EYE_RED 敌方）；头发分亮暗
  两级色块；服装多色块拼贴（作战服 #385238 + 护甲 #737A80 + 元素色点缀）。
  拒绝原版史蒂夫式单色粗颗粒。
- **Q 版比例**：头部可放大到身高的 1/4~1/3，肩窄、四肢短粗，优先可爱。
- **可动部件**：头/躯干/双臂/双腿/特征件各自独立 pivot（Transform 层级挂接），
  支持待机呼吸、走路摆臂、耳朵尾巴摆动——动画本身是该 mod 美学的一部分；
  头发/尾巴/耳朵可加物理摆动（YSM 1.2.0+ 支持物理模拟动画）。
- demo3d 现有角色由 voxel box 拼成；新增/改造干员按本规范补特征件与皮肤色块，
  材质从 PALETTE 色板取。

### 格式与动画词汇（照 YSM 的做法）

- **建模工具**：Blockbench（基岩版实体几何）——方块 + 各部件 pivot；YSM 的底座是
  GeckoLib + 基岩版模型/动画 JSON。当前 demo3d 角色由代码 voxel 拼装，比例与分件
  规范照用；做独立模型资产时，用 Blockbench 按同一规范制作。
- **动画状态清单**（每个角色应具备，命名 snake_case）：idle（待机呼吸）、walk、run、
  jump、hold_gun / aim / fire / reload——FPS 必备，YSM 与枪械 mod（TaC/TaCZ）的
  兼容动画就是这套持枪逻辑；再加 hurt、death；表情/互动动作走轮盘（YSM 按 Z 开
  动画轮盘，本作 3/4 键已是同款轮盘交互，可直接复用认知）。
- **贴图**：YSM 2.2.2+ 贴图上限 4096×4096，但早期模型包有 2MB 硬限制（过大同步失败）；
  本作 demo 有 GPU 内存缓慢增长的已知问题，角色贴图建议 ≤512×512，图标保持 128。
- **包结构**：YSM 模型包 = 模型 + 材质 + 动画放特定目录 + info.json，无需配置文件，
  游戏内重载指令热加载——与本项目"改配置表即时生效"哲学一致；本作资产同样
  按类型分目录、snake_case、放好即被 assets.load() 引用。
- **版权**：参考图中的 amiya 等是社区第三方 IP 模型，仅作风格基准；本作干员
  （焦狸/霜吻/雷豹/毒蜨）必须是原创设计，不照搬任何二次元 IP 形象。

## 量化美学规范（把形容词变成数字）

「圆润」「Q 弹」「轻描边」「小而精」不可执行，落进脚本必须是数字。下表是**默认起点**：
生成前先取值写进脚本常量，有意偏离时在交付汇报里写明偏离项与理由。
画布基准 128px；其他尺寸一律按**画布短边百分比**换算，保持视觉密度不变。

### 几何（图标 / 面板）

| 参数 | 规则 | 128px 画布取值 |
|---|---|---|
| 主体包围盒 | 画布短边 70–80% | 90–102px |
| 居中偏差 | ≤ 2px（视觉重心，非包围盒中心） | ≤ 2px |
| 外描边宽 | 短边 2.5–4% | 3–5px |
| 圆角半径 | 短边 8–15%，可爱取上限 | 10–19px |
| 内边距 | ≥ 短边 10%，主体不贴边 | ≥ 12.8px |
| 描边层数 | 只描最外轮廓一刀 | 1 层 |

方圆结合的做法：**整体轮廓倒圆角，内部体素/机械块保留直角**——可爱来自外轮廓，
硬朗来自内部结构，两者不冲突。

### 色彩

| 维度 | 规则 |
|---|---|
| 单图用色数 | ≤ 6（主 + 次 + 点缀 + 描边 + 高光 + 暗部） |
| 主 / 次 / 元素点缀占比 | 60–70% / 20–30% / 5–10%（60-30-10） |
| 军事底色饱和度 | S ≤ 0.40 |
| 元素点缀饱和度 | S ≥ 0.75 |
| 明暗层数 | 3 层：亮面 / 基色 / 暗面 |
| 相邻明度差 | ≥ 0.12（否则三层糊成一层） |
| 暗部下限 | ≥ 基色明度 − 0.25（避免死黑） |
| 主体 vs UI 深底 #1F242E | 对比度 ≥ 3:1（图形可辨下限，WCAG 1.4.11） |
| 正文文字分级 | 主要/次要 ≥ 4.5:1（WCAG AA）；弱化灰仅作装饰，不承载必读信息 |

辨识度靠**饱和度差**（低饱和军装 + 高饱和元素色）拉开，不靠堆色块数量。

### 像素 / 体素

| 参数 | 规则 |
|---|---|
| 网格 | 1 格 = 1 单位 |
| 贴图基准尺寸 | 16×16 或 32×32（≤512×512，见 GPU 内存注意事项） |
| 缩放过滤 | 一律 Nearest（最近邻），禁止线性/双线性糊边 |
| 轮廓线宽 | 1 单位 |
| 最小细节 | 禁止孤立 1×1 像素（糊成噪点即废） |
| 像素簇 | 同类像素成簇排列，色块边界走整数格 |

### 角色比例（1 单位 = 0.056m，总高 32 单位 ≈ 1.8m）

| 部位 | 原版骨架 | Q 版（本作取用） |
|---|---|---|
| 头 | 8×8×8（占身高 1/4） | 放大到身高 1/4–1/3（约 8–11 单位） |
| 头 : 身 : 肢 高比 | ≈ 1 : 1.5 : 1.5 | 头占比上探，身体相应压缩 |
| 身 | 8×12×4 | 保持 |
| 臂 / 腿 | 各 4×12×4 | 缩短约 10%，显短粗 |
| 肩宽 | — | 窄于头宽 ×1.5 |

特征件（兽耳/尾巴/发型块/帽子/武器）是辨识度主体，尺寸从骨架比例推导，
不独立放大到破坏整体剪影。

### 布局节奏（UI / 留白）

| 参数 | 规则 |
|---|---|
| 基础网格 | 8px |
| 间距档位 | 只取 4 / 8 / 12 / 16，不得出现 5、7、13 等非档位值 |
| 面板内边距 | ≥ 12px |
| 图标 | 标准 128×128 |

### 动画（可用 Bevy 时间轴/Tween 常量直接落值）

| 动作 | 时长 | 幅度 | 缓动 |
|---|---|---|---|
| idle 待机呼吸 | 周期 2–4s | 起伏 ≤ 身高 5% | ease-in-out |
| walk 走路 | 循环 0.8–1.0s | 摆臂 ±25° | ease-in-out |
| run 奔跑 | 循环 0.6–0.8s | 摆臂 ±35° | ease-in-out |
| aim / hold_gun 抬枪 | 0.15–0.25s | — | ease-in-out |
| fire 开火 | ≤ 0.1s 冲击 + 回位 | 后坐 ≤ 3° | ease-out |
| 耳/尾跟随 | 滞后本体 1–2 帧 | 摆幅为躯干 1.5–2× | 弹簧衰减 |

统一 **ease-in-out**，禁止线性（线性机械感破坏「Q 弹」）。

### 光照（3D 场景）

| 参数 | 规则 |
|---|---|
| 主光与水平面夹角 | 35–55°（太低显平、太高显顶光怪） |
| 环境光/补光占比 | ≥ 30%，避免暗面死黑 |
| 暗面亮度 | ≥ 基色明度 − 0.25 |
| 体素面区分 | 相邻面亮度差 15–25% |

## 风格基调

- **3D 像素（voxel）+ 可爱（cute/chibi）**：方圆结合、边缘圆润、比例 Q 弹；
  军事战术元素（作战服、护甲、警示条纹）用低饱和底色，元素/状态用高饱和点缀。
  对应上面的数字：外轮廓圆角 8–15%，军事底色 S ≤ 0.40，元素色 S ≥ 0.75。
- **图标**：128×128 PNG 透明底，扁平 + 轻描边（描边用 UI 深底 #1F242E 或同色系暗部），
  主体占画布约 70–80%，居中。
- **UI 背景**：深藏青系（#1F242E / #243347），信息层级靠文字三级灰蓝区分，
  交互态与选中用琥珀 #FFCC40，不用彩色大色块。
- **元素识别优先**：任何含元素的资产（武器、手雷、图标、特效）第一辨识度来自元素色，
  形状第二。

## 反模式（不要做）

- 用 JPG 存需要透明的图（图标/HUD）。
- 脱离本表自造近似色；或 demo3d 代码色与本表不同步。
- **交付形容词而非数字**：只说「圆润些」「Q 一点」「描边轻一点」却不给出半径/角度/宽度值。
- **单图用色超 6 种或主次占比失衡**，导致画面发花、失去元素辨识度。
- **贴图放大用线性插值**，糊掉像素硬边（像素风核心特征）。
- **动画线性缓动**，机械感破坏 Q 弹手感。
- 在核心库 `src/` 引用任何资产文件（核心库零 bevy，资产只归 demo 壳）。
- 特效逐发新建网格/材质——必须入池（历史 OOM 事故）。
- 尺寸失控的大图（4K 贴图等）：demo 有 GPU 内存缓慢增长的已知问题，资产保持小而精。
- 原版裸史蒂夫式角色（单色粗颗粒、无特征件、无动画分级）——钦定标准是 [YSM] 是，史蒂夫模型 mod 美学。
- 照抄第三方 IP 形象（参考图里的 amiya 等仅作风格基准，干员一律原创设计）。
